## Anti-Patterns Verdict

**LLM assessment:** The design passes. The blueprint grid, corner bracket hover mechanic, orange accent on near-black, and specific About copy distinguish this from the generic developer portfolio. A visitor won't immediately say "AI made this" — the visual identity has enough deliberate choices.

Two risks worth naming:

1. **Geist is the canonical 2024-2026 developer-portfolio font.** It's Vercel's own variable font and it's on roughly 60% of developer portfolios built in this era. The design is otherwise distinctive — the font is the one place where the identity blends into the background noise. It doesn't sink the design but it's the single weakest identity choice.

2. **Numbered section markers ("01 / About" through "06 / Contact")** are the banned scaffolding pattern used on every section. The partial defense — numbers matching navbar indices — is real; they function as a navigation system. But they read as AI scaffolding to a critical eye. One strong differentiator would neutralize this; as-is it's the loudest visual grammar tell.

**Deterministic scan (detector, exit code 2):** 4 findings:
- **2× Overused font** — Geist and Geist Mono at `index.css:3` and `index.css:11`. Legitimate finding (see above).
- **1× Bounce easing** — `animate-bounce` (Tailwind) at `index.css:2794`. **False positive** — this is in dead legacy CSS inside `@layer components .cta-button` which is not referenced by any active component.
- **2× Layout property animation** — `transition: width` at `index.css:721` and `index.css:2619`. **False positive** in both cases — these animate the width of 1px pseudo-element underline decorations (`.navbar-link::after` and `.footer-back-to-top-button::after`). No layout thrash risk.

No browser injection was performed (no dev server running at critique time).

## Overall Impression

The visual system is confident and specific — the grid, the orange, the technical card treatment all cohere. What undermines the credibility is entirely content-level: the Projects section shows a single project with `example.com` links, and 5 other projects sit in the data file without ever rendering. A hiring manager who reaches the Projects section and clicks "Live site →" lands on a placeholder. That single moment erases much of the trust the earlier sections built.

Fix the projects data and render the grid. Everything else is refinement.

## Priority Issues

**[P1] Projects data is entirely placeholder — active credibility threat**
- **What**: All 6 project entries use `liveUrl: "https://example.com"` and `githubUrl: "https://github.com/username/..."`. The featured project title is "E-Commerce Platform" — generic enough to be from any template.
- **Why it matters**: A hiring manager who reaches Projects is evaluating work quality. Clicking "Live site →" and landing on example.com immediately signals "this portfolio is unfinished." It actively undermines the credibility built by the specific About bio and detailed timeline.
- **Fix**: Replace all entries in `src/data/projects.ts` with real projects, real URLs, and real descriptions. If a project has no live URL, omit the `liveUrl` field rather than linking to a placeholder.
- **Suggested command**: `/impeccable clarify` (copy) + `/impeccable harden` (real data)

**[P1] Projects grid never renders — section is visually incomplete**
- **What**: `Projects.tsx` only calls `<FeaturedProject />`. The `ProjectCard` component, `.projects-grid` CSS, and `.filter-bar` CSS all exist but `Projects.tsx` never renders them. 5 of 6 projects are invisible on the page.
- **Why it matters**: The section ends after a single project card. Visitors see a section heading and one item — it looks truncated, not curated.
- **Fix**: Add the filter bar and project grid back to `Projects.tsx`. Wire `ProjectCard` components for non-featured entries.
- **Suggested command**: `/impeccable craft projects grid`

**[P2] Education and Projects section index numbers are swapped**
- **What**: Education displays `"05 / Education"` but it's the 4th section (navbar index `"04"`). Projects displays `"04 / Projects"` but it's the 5th section (navbar index `"05"`). They're transposed — a copy-paste error.
- **Why it matters**: The numbered system is only compelling if the numbers are accurate. A visitor who cross-references the mobile nav (which shows the correct indices) will notice the mismatch.
- **Fix**: Change `Education.tsx` → `"04 / Education"`, `Projects.tsx` → `"05 / Projects"`.
- **Suggested command**: `/impeccable polish`

**[P2] `back.out(1.7)` easing on timeline node entrance animation**
- **What**: `WorkExperience.tsx:67` — `ease: "back.out(1.7)"` on timeline node scale animation. Back easing overshoots and recoils — it's a near-bounce.
- **Why it matters**: The rest of the motion system uses `power3.out` consistently. This one node animation feels visually inconsistent — slightly bouncy and frivolous against the otherwise precise motion language.
- **Fix**: Change to `ease: "power3.out"` or `"elastic.out(1, 0.4)"` at low amplitude if overshoot is desired with intent.
- **Suggested command**: `/impeccable animate`

**[P2] Geist is the highest-saturation developer font of its generation**
- **What**: Both `Geist` and `Geist Mono` are flagged by the detector. Geist ships as Vercel's own variable font and dominates 2024-2026 developer tooling. The portfolio's target audience (technical hiring managers) will have seen it on dozens of portfolios.
- **Why it matters**: The brief is "technical, precise, sharp." Geist delivers on that brief — but so do Söhne, Roc Grotesk, Aktiv Grotesk, ABC Diatype, or Unica77. A less-ubiquitous choice would sharpen the identity without changing the voice.
- **Fix**: Not urgent — the design has enough other distinguishing features that this doesn't sink it. If pursued, consider replacing display usage with a less common variable sans (keeping Geist Mono for code labels is more defensible since mono fonts have smaller saturated sets).
- **Suggested command**: `/impeccable typeset`

## Persona Red Flags

**Jordan (First-Timer / Recruiter scanning multiple portfolios):**
Lands on the page, reads the hero — strong. Scrolls to Projects (the section recruiters care most about). Sees one project. Clicks "Live site →". Lands on `example.com`. Immediately loses trust. **Abandonment risk is high after this interaction.** The section even has a subtitle: "A curated selection of what made it past the idea stage" — which now reads as cover for an unfinished section.

**Casey (Mobile / Distracted user on phone):**
Navigation works well (hamburger, escape, focus trap all solid after recent fixes). The hero CTA stack looks fine. The timeline alternating left/right becomes left-only on mobile — the layout adapts correctly per the CSS. **One concern**: the bento grid collapses to 12-column single-column stack at 980px, which on a phone means scrolling through 6 stacked tiles of similar visual weight. There's no summary or collapsed view for mobile. Minor but real.

**Hiring Manager (Project-specific persona):**
An engineering director evaluating candidates has 5 minutes and 20 tabs open. They want: evidence of shipping, stack breadth, a way to contact quickly. The Work Experience section delivers on shipping evidence. The Skills bento delivers on stack breadth. Contact is accessible from the nav. **The Projects section is the only major miss** — this persona specifically checks project quality and example.com links read as a disqualifier rather than a placeholder.

## Minor Observations

- **FeaturedProject image alt text** — `alt={project.title}` (FeaturedProject.tsx:48) describes the project name, not what the image shows. For a portfolio screenshot, the alt text should describe the interface: "Screenshot of the e-commerce platform dashboard showing product listings."
- **`animate-bounce` in dead CSS** — `@layer components .cta-button .arrow-wrapper img` at `index.css:2794` contains `animate-bounce`. This CSS block is unreferenced by any active component (legacy from a prior iteration). Safe to delete the whole `.cta-button` component block.
- **Contact subtitle copy** — "Let's build something that matters." — classic aphoristic close. Specific would be stronger: "I read every message and usually reply the same day." or similar.
- **WorkExperience subtitle** — "Building products and leading teams across the tech stack" — slightly generic compared to the bio's voice. A specific claim ("Seven years, three funding rounds, one rewrite I'm proud of") would land harder.
- **CLAUDE.md architecture note** — states `App.tsx` renders sections as `Navbar → Hero → Skills → WorkExperience → Education → Projects → Contact → Footer` but the About section exists and has a nav entry. The docs may be outdated.
- **`text-wrap: balance` missing** — Hero title (`h1`) and section titles (`h2`) don't use `text-wrap: balance`. On medium viewports, the two-word hero title ("Martin / Romano.") doesn't need it, but multi-word section titles like "Work Experience" or "Selected work" could benefit.
